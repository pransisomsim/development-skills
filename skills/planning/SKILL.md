# Planning

Before implementation:

1. Understand the existing architecture.
2. Inspect relevant files.
3. Identify current behavior.
4. Identify affected modules.
5. Identify database/API implications.
6. Identify risks and edge cases.
7. Produce an implementation plan.

Do not modify files.

The plan should contain:

- Goal
- Current behavior
- Proposed change
- Files to modify
- Files to create
- Database changes
- API changes
- Validation/error behavior
- Edge cases
- Testing strategy

Do not invent requirements.

If existing architecture conflicts with the requested change, explain the conflict before proposing a solution.
